# Spec

## Intent

Все четыре файловых инструмента агента (`read`, `ls`, `find`, `grep`) должны отказывать в доступе к секретам пользователя, транскриптам других агентов и приватным данным приложения, включая случай, когда запрещённый путь достигается через symlink. Ключевые значения, попавшие в легитимно прочитанный текст, маскируются в выводе инструмента.

База — локальная ветка `pr-421` (upstream PR #421): она даёт отказ для `.claude`, `.ssh`, `.aws`, `.env`. Эта задача добавляет поверх неё app-private deny-list, realpath-проверку и маскирование.

Контракт, который обязан существовать после реализации (единственный модуль с политикой):

`src/agent/tools/fs-deny.ts`

```ts
export interface DenyScope {
	home: string;        // абсолютный путь
	dataDir: string;     // резолв LH_DATA_DIR, дефолт <repo>/data
	authFile: string;     // резолв LH_AUTH_FILE, дефолт <repo>/auth.json
	extraDirs: string[]; // дополнительные приватные корни, могут быть пустыми
}

/** home из os.homedir(), dataDir/authFile из LH_DATA_DIR/LH_AUTH_FILE (дефолты как в docs/development.md),
 *  extraDirs содержит process.env.LH_USER_DATA_DIR, когда он задан (упакованный Electron). */
export function defaultDenyScope(): DenyScope;

export interface AccessVerdict { allowed: boolean; reason?: string }

/** Проверка по realpath (существующая часть пути) с откатом на нормализованный литеральный путь. */
export function checkPathAccess(absolutePath: string, scope?: DenyScope): Promise<AccessVerdict>;

/** Бросает FileAccessDeniedError, если доступ запрещён; иначе resolve. */
export function assertPathAllowed(absolutePath: string, scope?: DenyScope): Promise<void>;

export class FileAccessDeniedError extends Error {
	readonly name: "FileAccessDeniedError";
	readonly code: "file_access_denied";
}

/** Заменяет key-like значения ровно на маркер `[redacted]`, оставляя имя ключа/окружающий текст.
 *  Идемпотентна: redactSecrets(redactSecrets(x)) === redactSecrets(x). */
export function redactSecrets(text: string): string;
```

Обязательный минимум политики (модуль может запрещать больше, но не меньше):

| Категория | Обязательно запрещено | `reason` |
|---|---|---|
| credentials | `~/.ssh/**`, `~/.aws/**`, `~/.gnupg/**`, `~/.netrc`, `~/.npmrc`, `~/.git-credentials`, `~/.config/gh/**`, `~/.config/gcloud/**`, `~/.docker/config.json`, `~/.kube/config`, любой файл с basename `.env` или начинающимся с `.env` | `credentials` |
| agent-transcripts | `~/.claude/**`, `~/.codex/**`, `~/.gemini/**` | `agent-transcripts` |
| app-private | каталог `dataDir` целиком; файл `authFile`; любой файл с basename `auth.json`, `chatgpt-credentials.json`, `github-copilot-credentials.json`, `xai-credentials.json`; каждый каталог из `extraDirs` | `app-private` |

Правила проверки:

1. Вход — абсолютный путь (после `resolveSourcePath`). Guard нормализует `path.resolve`, затем разрешает symlink'и по максимально длинному существующему префиксу и ещё раз нормализует.
2. Сравнение — по границам сегментов пути (никакого `startsWith` по строке: `/home/u/.ssh2` не запрещён, `/home/u/.ssh/x` запрещён).
3. Если realpath не вычислим — вердикт по нормализованному литеральному пути (fail-closed, отказ возможен и для несуществующего файла).
4. `home` сам по себе и всё, что не попало в таблицу, разрешено.
5. `EXCLUDED_DIR_NAMES` в `fs-shared.ts` остаётся как есть и продолжает действовать при обходе; запрет доступа — отдельная проверка, применяемая и к явным путям.

Интеграция инструментов:

- `read` — `assertPathAllowed` вызывается до `detectSupportedImageMimeTypeFromFile`/`fs.readFile`; текст результата проходит `redactSecrets`.
- `ls`/`find`/`grep` — `walkFiles` (или эквивалент) не заходит в каталог и не открывает файл, если `checkPathAccess` вернул `allowed: false`; содержимое файла не читается до вердикта (включая `isBinaryFile`).
- `capOutput` в `fs-shared.ts` применяет `redactSecrets` к каждой строке до проверки лимита байт, поэтому лимит считается по уже замаскированному тексту.
- Блокирующий вердикт — значение `REASON`-категории, использованное в сообщении: `file access denied (<reason>): <path>`.

## When

Исполнитель берёт `pr-421` как базу, добавляет модуль `src/agent/tools/fs-deny.ts` с контрактом выше, подключает его к `read`/`ls`/`find`/`grep` и к `capOutput`, добавляет юнит-тесты в `tests/`, прогоняет `dod`, `npm test`, `npm run typecheck`, `npm run lint`.

## Then

- `read` по `auth.json`, `~/.ssh/id_rsa`, `.env`, `~/.aws/credentials`, `~/.claude/projects/<id>/*.jsonl`, `dataDir/chats/*.json` возвращает ошибку инструмента с `file access denied`, файл не читается.
- `read` по symlink, указывающему в запрещённую область (файл или каталог), отклоняется так же; symlink на разрешённый файл читается.
- `ls`/`find`/`grep` не показывают содержимое запрещённых каталогов и файлов при обходе home.
- Обычные файлы (`~/notes/*.md`, `~/Documents/*`, `~/project/src/*`) читаются и находятся как раньше.
- В выводе любого файлового инструмента key-like значение (OpenAI `sk-*`, GitHub `ghp_*`/`github_pat_*`, AWS `AKIA*`, Google `AIza*`, PEM private key, значение после `password|secret|token|api_key` длиной ≥ 12) заменено на `[redacted]`; имя ключа и окружающий текст сохранены.
- `npm test`, `npm run typecheck`, `npm run lint` зелёные на Node 26.
- `dod` зелёный; с `oracle/negative/<ID>/kit.patch` (заглушка «всегда разрешено») `dod` красный.

## Forbidden

- Править приложение вне `src/agent/tools/**` и `tests/*.test.ts` (в частности `electron/`, `src/server/`, `src/store/`, `docs/`).
- Добавлять настройку или env-переменную, отключающую deny-list, и любой «разрешить на один раз» путь.
- Делать `resolveSourcePath` асинхронной, I/O-зависимой или возвращающей вердикт.
- Реализовывать проверку после чтения файла, после `isBinaryFile` или после формирования вывода (в т.ч. «прочитать и выбросить»).
- Ловить и глотать `FileAccessDeniedError` внутри инструмента, превращать отказ в пустой успешный результат или в ENOENT.
- Скрытые ретраи, фоллбэки на «первый разрешённый родительский каталог», эвристики «файл похож на секрет — пропустить».
- Мыть окно вывода: менять форматы, тексты подсказок, лимиты 50KB/2000 строк/500 символов и `EXCLUDED_DIR_NAMES` в рамках этой задачи.
- Править `package.json` (добавлять зависимости), `tsconfig.json`, `eslint.config.mjs`.
- Ослаблять или удалять существующие тесты файловых инструментов, включая тесты из `pr-421`.
