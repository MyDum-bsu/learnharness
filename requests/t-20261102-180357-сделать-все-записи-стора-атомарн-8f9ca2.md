# Raw request

Сделать все записи стора атомарными, чтобы падение процесса не стирало сессию или настройки. Основание: локальная ветка pr-433 (upstream PR #433 atomic writes, 17 файлов, +573/-71, тесты, mergeable в dev) и ревью .agent/review-2026-11-02.md §3.1. Симптом: при crash или force quit во время сохранения chats/<id>.json файл остаётся пустым, сессия исчезает из sidebar, ссылка даёт 404. То же для settings.json, jobs/<id>.json, graph/sources.json. Evidence: src/store/chats.ts:57-59 пишет fs.writeFileSync прямо в целевой файл, src/store/settings.ts:57, src/store/jobs.ts:45,65. Читатели глотают parse error и возвращают null или пустой объект: src/store/chats.ts:61-76, src/store/settings.ts:39-43, src/store/jobs.ts:51-56. Требование: один writeFileAtomicSync (temp в том же каталоге, fsync файла и каталога, rename) для всех store-записей: chats, settings, jobs, graph sources, auth. Битый файл при чтении даёт явную ошибку и лог, а не тихий null. Формат данных на диске не менять. Приёмка: регрессионный тест, который в цикле убивает процесс во время сохранения, и после каждого прогона файл парсится, а сессия восстанавливается; плюс тест на битый JSON, дающий наблюдаемую ошибку. Все тесты зелёные на Node 26. Риск medium, затрагивает персистентность. Не смешивать с другими P0: только атомарность записи.
