# PRD — закрыть dev/start-сервер от локальной сети

## Goal

`npm run dev` и `npm start` перестают быть доступны с других устройств в LAN: оба скрипта запускают Next с явным `-H 127.0.0.1`, а `docs/development.md` фиксирует, что standalone-запуск требует `HOSTNAME=127.0.0.1`.

Сейчас `package.json` (`scripts.dev: "next dev"`, `scripts.start: "next start"`) отдаёт сервер на `0.0.0.0`, и `desktopAPIAuthorized` пропускает всё при отсутствии desktop-секрета (`src/server/desktop-access.ts:5-15`). Телефон в той же сети видит UI, `/api/keys`, настройки и SSE. Ревью: `.agent/review-2026-11-02.md` §3.5.

## Non-goals

- `electron/main.cjs` не трогать: упакованный desktop уже слушает loopback с desktop-секретом.
- `scripts/build-server.mjs` не трогать: hostname там не задаётся, дефолт standalone-сервера — отдельная задача p1-1.
- Не менять `desktop:dev` (он вызывает `next dev` напрямую) и вообще не трогать рантайм-логику, auth, proxy, SSE.
- Не добавлять аутентификацию, pairing, device tokens, server mode — это §4 ревью, не эта задача.
- Никаких изменений в `docs/architecture.md`, README и прочих документах.

## Use cases

1. Разработчик запускает `npm run dev` и открывает `http://localhost:3000` — работает как раньше.
2. Телефон из той же сети открывает `http://<LAN-IP>:3000` — соединение отклонено (сервер не слушает LAN-интерфейс).
3. Разработчик поднимает standalone-сборку, читает `docs/development.md` и запускает её с `HOSTNAME=127.0.0.1`, тем самым не выставляя её в сеть.
4. CI/тесты запускают `npm test` — поведение не меняется, скриптов это не касается.

## UX

Внешнего UI-изменения нет. Видимый эффект — только для того, кто подключался к dev/start-серверу с другого устройства: страница больше не открывается (connection refused). Локальная работа через `localhost` не меняется.

Для standalone: явное требование в документации (`HOSTNAME=127.0.0.1`) вместо неявного `0.0.0.0`.

## Edge cases

- `npm run dev -- --port 3001` (`docs/development.md`) — дополнительный аргумент после `-H 127.0.0.1` должен продолжать работать; Next принимает оба флага независимо от порядка.
- Пользователь, которому нужен LAN-доступ (телефон в отладке), теперь получает отказ по умолчанию; вернуть доступ можно только вручную, дописав `-H 0.0.0.0`, — это осознанный выбор, а не регрессия.
- `npm run desktop:dev` вызывает `next dev` напрямую и остаётся на `0.0.0.0`; Electron в этом режиме ходит на `http://localhost:3000`, поэтому не ломается. Остаточный риск зафиксирован в Risks.
- IPv6: `localhost` может резолвиться в `::1`; `-H 127.0.0.1` привязывает только IPv4. Браузер на той же машине обычно пробует оба адреса, `http://localhost:3000` продолжает открываться; `http://[::1]:3000` — нет.
- Standalone, запущенный без переменной, по-прежнему слушает `0.0.0.0` — именно поэтому дефолт меняется отдельной задачей p1-1, а здесь фиксируется только требование к запуску.

## Risks

- `desktop:dev` остаётся открытым в LAN (вне скоупа по постановке). Риск принимается явно; закрывается либо в p1-1, либо отдельной задачей про dev-скрипты Electron.
- Ложное чувство защищённости: loopback-привязка не является аутентификацией. `docs/development.md` уже говорит, что это trusted developer-server mode; правка документа не должна ослабить это предупреждение.
- Кто-то полагался на LAN-доступ к dev-серверу (например, тестировал на телефоне) и воспримет это как поломку. Митигация — явная строка в документации о `-H 0.0.0.0` как ручном исключении.
- Правка `docs/development.md` может задеть соседние абзацы. Скоуп — минимальная вставка, без переписывания раздела.

## Verification plan

1. `dod`-команда (одна, читает `package.json` и `docs/development.md` через oracle-скрипт): падает на текущем состоянии, проходит после правки.
2. Негативный контроль: `oracle/negative/<ID>/kit.patch` возвращает `next dev` / `next start` без `-H`; после применения `dod` обязан снова упасть.
3. `git diff --name-only` после работы — ровно `package.json` и `docs/development.md`.
4. Полный `npm test` / `npm run build` не запускаются: рантайм-код не затронут, изменение — две строки скриптов плюс документация.
